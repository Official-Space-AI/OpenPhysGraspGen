# Community

## Where to ask what

| Purpose | Place |
|---|---|
| Installation and usage questions | [Discussions → Q&A](https://github.com/Official-Space-AI/OpenPhysGraspGen/discussions/categories/q-a) |
| Reproducible bugs | [Issues → Bug report](https://github.com/Official-Space-AI/OpenPhysGraspGen/issues/new/choose) |
| Feature ideas | [Discussions → Ideas](https://github.com/Official-Space-AI/OpenPhysGraspGen/discussions/categories/ideas) |
| Agreeing on work before a pull request | An issue linked from the pull request |
| Dataset questions (schema, samples, license) | The Community tab of the Hugging Face dataset (from `1.0.0rc1`) |
| Release and roadmap announcements | [Discussions → Announcements](https://github.com/Official-Space-AI/OpenPhysGraspGen/discussions/categories/announcements) |
| Security vulnerabilities | Never in public. See [SECURITY.md](SECURITY.md) |

GitHub is the system of record. When a bug, decision or frequently asked question
comes up anywhere else (chat, email, a meeting, the Hugging Face page), a maintainer
summarizes it in a GitHub issue or discussion and links the two. Use the
**Community → issue** form for this.

Do not post access tokens, passwords, personal data or unpublished
vulnerabilities in any public channel.

## Response expectations

- Hours: weekdays 09:00–18:00, Asia/Seoul (KST)
- First triage of new issues and discussions: within **48 hours**
- Answers in community channels are best effort and are not a support contract.

## Triage

The maintainers listed in [GOVERNANCE.md](GOVERNANCE.md) triage new issues and
discussions. Triage means:

1. Label the item (`bug`, `enhancement`, `question`, `documentation`, …) and
   remove `triage`.
2. Ask for missing information, or close duplicates with a link to the original.
3. Move usage questions that were filed as issues to Discussions.
4. Mark small, well-scoped items `good first issue` and keep at least five of
   them open.
5. Turn repeated questions into documentation or an FAQ answer.

Items waiting for information from the reporter for 14 days may be closed; they
can be reopened at any time.

## Code of Conduct

Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Health metrics

Maintainers review these monthly and publish a short summary in Announcements:
time to first response, open issues without triage, new and returning
contributors, issues and pull requests opened and closed, and releases.
